다음 개발 세션 대화에서 아래 항목을 중심으로 요약하라:
- 내린 기술적 결정과 그 이유
- 실수나 수정 사항
- 새로 배운 점 (TIL)
- 흥미로운 발견이나 의문점
원문의 구체적 기술 용어와 맥락을 보존하라.
이 입력은 세션 전체가 아니라 원래 순서를 유지한 한 조각입니다. 조각 번호와 시간순 변화를 보존합니다. 초기에 A를 택했다가 B로 바꿨다면 이전 선택과 변경 이유, 마지막 선택을 구분합니다. 실패가 뒤에서 해결됐으면 실패를 현재 상태로 남기지 않습니다. 마지막 사용자 정정과 그 대상 발언, 아직 해결하지 못한 사항을 우선 보존합니다. 이 조각에서 알 수 없는 최종 상태는 추측하지 않습니다. 출력 길이가 부족하면 앞부분의 세부 사항보다 마지막 결정, 해결 여부와 정정의 맥락과 근거를 우선합니다.
같은 [mN]이 반복되면 긴 원문 발언을 나눈 부분입니다. 발언자와 ID를 각 인용에 유지합니다. 이 요약 자체는 합성 설명이며 원문 발언이 아닙니다. 합성 설명을 인용하거나 새 발언 ID를 만들지 않습니다. 원문 인용과 요약 설명을 구별합니다.
결정, 명시된 이유, 정정과 사용자의 실제 학습을 뒷받침하는 [mN] 발언 ID, 발언자와 짧은 원문 인용을 보존합니다. 인용을 번역하거나 만들거나 다른 발언의 ID를 붙이지 않습니다. 사실 오류 정정과 선호 또는 접근 방식 변경을 구분하며 모호하면 unknown으로 남깁니다. 인용을 보존할 수 없으면 해당 인사이트를 제외합니다.
`[REFERENCE <UTC 시각>; prior context only]` 발언은 과거 참고 자료입니다. 원래 ID와 참고 시각을 유지하고 대상 날짜 발언과 구분합니다. 참고 자료의 결정과 학습을 당일 새 항목으로 만들지 않습니다. 오늘의 정정과 최종 결론을 우선하며 과거 답변과 오늘 정정을 연결할 때 날짜와 각각의 인용을 보존합니다.
