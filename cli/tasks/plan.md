작성일: 2026-10-25
기준 명세: [SPEC.md](../SPEC.md)(2026-10-25 승인)
기준 코드: `main` 브랜치 `339ece4`
작업 목록: [todo.md](todo.md)

## 개요

명세의 네 단계를 작업 12개로 나눴습니다. 1단계는 Claude와 Codex 수집 코드를 어댑터로 옮기고 `run_today`, 캐시, 정보 상자, `rwd doctor`가 어댑터 목록만 보게 바꿉니다. 2단계는 LLM을 부르지 않는 `rwd today --dry-run`을 넣습니다. 3단계는 Antigravity의 `transcript_full.jsonl`을 읽는 어댑터와 릴리스 노트 안내를 넣습니다. 4단계는 Claude와 Codex의 서브에이전트 결과를 부모 세션 프롬프트에 붙입니다. Antigravity 서브에이전트는 4단계에서 뺍니다.

각 작업은 끝났을 때 `cargo build`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked`를 통과하는 상태로 둡니다. 작업 하나가 끝날 때마다 로컬 커밋을 합니다.

## 구조 결정

- 어댑터는 쓰기 전에 먼저 만들고, 바꿔 끼우는 작업은 한 번에 합니다. 작업 1과 2는 새 `sources` 모듈에 Claude와 Codex 어댑터를 만들기만 하고 기존 코드는 그대로 둡니다. 작업 3에서 `commands/`가 어댑터를 쓰도록 한 번에 바꾸고 옛 수집 함수를 지웁니다. 옛 함수와 새 어댑터가 함께 있는 동안 둘의 결과를 비교하는 테스트를 돌려서, 바꿔 끼우기 전에 결과가 같다는 것을 확인합니다.
- 작업 1~3 동안만 `sources` 모듈에 `#[allow(dead_code)]`를 둡니다. CI가 `clippy -D warnings`로 돌아서, 아직 아무도 부르지 않는 새 코드가 있으면 실패하기 때문입니다. 작업 4에서 지웁니다.
- 테스트는 실제 홈 폴더를 읽지 않습니다. 이 프로젝트는 `unsafe`를 쓰지 않아서 테스트에서 `HOME` 환경 변수를 바꿀 수 없습니다(Rust 2024에서 `std::env::set_var`는 `unsafe`입니다). 그래서 어댑터마다 찾을 폴더를 직접 넘기는 생성 함수(`with_roots`)를 두고, 테스트는 임시 폴더만 넘깁니다. 수집 함수도 어댑터 목록을 인자로 받아서, 테스트에서 가짜 어댑터를 넣을 수 있게 합니다.
- `--dry-run` 경로는 LLM 제공자, 캐시, Markdown 저장 함수를 받지도 부르지도 않는 별도 함수로 만듭니다. 명세는 제공자 불러오기를 인자로 받아 테스트하는 방법을 적었지만, 그보다 강한 보장입니다. 함수가 그 기능에 닿을 수 없어서, 코드 검토와 함께 출력 함수 테스트로 확인합니다.
- 서브에이전트 줄은 시각 순서로 프롬프트에 끼워 넣습니다. 작업 10에서 프롬프트 조립 함수가 서브에이전트 목록을 함께 받고, 각 줄의 시각보다 늦은 첫 메시지 앞에 넣습니다. 목록이 비어 있으면 지금과 똑같은 프롬프트가 나와야 합니다. `analyzer`는 `sources`를 모르게 두려고, 프롬프트 조립 함수는 시각과 역할과 글만 담은 줄 목록을 받고, 서브에이전트 타입과 길이 상한은 `sources/subagent.rs`에 둡니다.
- 4단계 시작 전(2026-10-25)에 실제 로그로 다시 세어 보고 명세 4단계 절을 두 군데 고쳤습니다. Codex 서브에이전트 기록은 맨 앞에 부모 대화를 복사해 담고 있어서, 맡긴 일은 자기에게 온 첫 `agent_message` 글로, 결과는 그 뒤 마지막 답변으로 바꿨습니다. Claude의 맡긴 일은 길게는 99,073자(부모 세션 합계 최대 168,530자)라서, 맡긴 일도 하나당 2,000자, 세션 합계 6,000자로 자르기로 했습니다. 그래서 확인 지점 4의 토큰 기준은 약 12,000개에서 약 15,000개로 바뀝니다. 숫자는 명세의 길이 상한 절과 출처별로 읽는 곳 절에 있습니다.
- PR은 단계마다 하나씩 냅니다. 명세가 단계마다 배포할 수 있게 정했기 때문입니다. 작업 9(릴리스 노트 스크립트)는 3단계 PR보다 먼저 들어가야 3단계 릴리스 노트에 안내가 나옵니다.

## 의존 관계

```text
작업 1 Claude 어댑터 ──┐
작업 2 Codex 어댑터 ───┴─> 작업 3 commands 전환 ─> 작업 4 doctor와 정리
                                                    │
                                                    └─> 작업 5 --dry-run
작업 6 Antigravity 기록 읽기 ─────────────────────────────> 작업 7 Antigravity 어댑터 ─> 작업 8 문서와 실제 로그 확인
작업 9 릴리스 노트 스크립트 (독립, 3단계 PR 전에 끝냄)
작업 4 ─> 작업 10 서브에이전트 줄과 상한 ─> 작업 11 Claude 서브에이전트
                                         └─> 작업 12 Codex 서브에이전트
```

작업 7은 작업 4(어댑터 목록 정리)와 작업 6에 기대고, 실제 로그 확인(작업 8)은 작업 5의 `--dry-run`이 있어야 합니다.
