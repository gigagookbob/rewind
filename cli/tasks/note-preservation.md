# 일일 노트 보존 구현 계획

1. 기존 전체 덮어쓰기의 데이터 손실을 합성 노트로 재현합니다. 자동 영역 비교와 파일 교체를 구현하고 `save_to_vault`에 연결합니다.
2. 같은 저장 경계에 진행 요약을 연결하고 명령의 저장 실패를 반환합니다. 순서 변경, 캐시 재저장, 표시 충돌과 파일 오류를 검증합니다.
3. 전체 오프라인 검사와 자체 리뷰를 마치고 부모 리뷰의 필요한 수정을 처리합니다. 검증한 변경만 로컬 커밋합니다.

- [x] 사용자 메모, 앞머리와 표시 없는 기존 결과를 보존합니다.
- [x] 분석과 요약을 반복하거나 순서를 바꿔도 각 자동 영역은 하나만 남습니다.
- [x] 수동 수정과 잘못된 표시, 코드 상자를 보수적으로 처리합니다.
- [x] 잠금과 임시 파일 교체, 읽기와 쓰기 오류를 검증합니다.
- [x] 저장 실패가 명령과 백그라운드 완료로 이어지지 않는지 확인합니다.
- [x] 빌드, Clippy, 전체 테스트, 포맷과 문서 검사를 통과합니다.
- [x] 자체 리뷰, 변이 검사와 부모 리뷰 후 로컬 커밋과 5번 경계 인계를 마칩니다.

## 확인 결과

2026-11-02에 전체 379개 테스트, 빌드, Clippy와 포맷 검사가 통과했습니다. 테스트, 빌드와 Clippy는 `--offline --locked`로 실행했으며 실제 앱, AI 공급자, 알림과 Obsidian 노트는 호출하지 않았습니다. 테스트의 비동기 경로는 합성 결과만 처리하며 업데이트 요청과 알림 경로는 본체 진입점에 남아 있어 실행하지 않았습니다.

최초 회귀 검사에서는 기존 메모가 전체 덮어쓰기로 사라지는 실패를 확인한 뒤 수정했습니다. 체크섬 비교를 잠깐 제거한 변이 검사에서도 영역 안의 수동 메모를 보호하는 테스트가 실패했고 원래 파일 바이트로 복원했습니다. 복원 뒤 전체 검사를 통과했습니다. 부모가 지적한 일반 문장 속 `rwd:` 오인도 HTML 주석 후보로 범위를 좁히고 회귀 테스트에 포함했습니다.

파일 검사에는 잘못된 UTF-8 읽기, 출력 경로가 파일인 경우, 잠금 충돌과 해제 후 재실행, 외부 변경과 삭제, 실패한 이름 변경, 임시 파일 정리, 심볼릭 링크 거부와 일반 권한 보존을 포함했습니다. 저장 오류는 두 명령의 `?`와 백그라운드의 기존 `Result` 분기를 코드 리뷰로 확인했습니다. 실제 알림을 보내는 실행 검사는 하지 않았습니다.

한국어 문서 검사에서 새 명세와 계획, README에 추가한 부분은 통과했습니다. README 전체에서는 기존 영어 부분의 엠 대시와 이전 문단의 검토 항목이 검출됐으며 이번 범위 밖이라 보존했습니다.

부모가 최종 저장 정책, 파일 교체, 명령 연결과 테스트를 읽고 일반 `rwd:` 문자열 수정 외에 추가 필수 수정을 발견하지 않았다고 확인했습니다. 검증한 변경만 로컬 커밋하며 푸시는 하지 않습니다.

## 남은 한계

영역 안을 편집하면 어느 쪽 명령이든 저장을 멈춥니다. 구 결과를 제목으로 찾아 제거하지 않아 첫 이행에서 예전 분석과 새 분석이 나란히 남을 수 있습니다. 임시 파일과 고정 잠금 파일은 실제 사용자 노트를 일괄 수정하거나 정리하지 않습니다. 마지막 확인과 교체 사이의 외부 편집, 동기화 서비스, 전원 장애와 확장 파일 속성 보존은 검증 또는 보장 범위에 포함하지 않습니다. 실제 노트와 외부 AI를 사용하는 종단 검사는 하지 않았습니다.

## 5번에 넘길 호출 경계

`src/analyzer/executor.rs`의 `prepare_analysis_input`은 최종 분석 입력에서 설정에 따라 마스킹합니다. 그 전에 `summarizer.rs::summarize_chunks`는 원문 조각을 `provider.call_text_api`로 보냅니다. `analyzer/mod.rs::analyze_summary`와 `analyze_slack`도 캐시의 작업 요약을 공급자에 바로 전달합니다. 다음 작업은 이 세 경로와 재시도, Anthropic, OpenAI와 Codex의 실제 전송 경계를 함께 확인해야 합니다.

4번은 저장 결과를 감싸는 주석만 추가했으며 JSON 캐시, 원문 인용과 실제 파일 및 줄 위치, 정정 분류, 부분 분석 표시와 참고 시각은 바꾸지 않았습니다. 5번에서 마스킹 위치를 옮기면 근거 원문 대조와 입력 길이 계산, 캐시 사용 시의 표시 재검사도 함께 유지해야 합니다. 5번 구현은 시작하지 않았습니다.
