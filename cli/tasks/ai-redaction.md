# AI 전송 마스킹 구현 계획

기존 `tasks/plan.md`와 `tasks/todo.md`의 다른 작업을 보존하고 이 작업은 별도 파일에서 관리합니다. 범위는 [명세](../SPEC-ai-redaction.md)에 따릅니다.

1. 탐지 규칙의 API 키와 개인키 누락, 메시지 경계 분할을 합성 테스트로 재현합니다. 기존 규칙을 최소 수정하고 마스킹 범위를 메시지별로 보존합니다.
2. 공급자에 설정 정책과 공통 입력 검사를 연결합니다. 실제 HTTP 본문과 Codex 표준 입력을 만들고 가짜 전송으로 검사합니다.
3. 원문 분할 전 마스킹을 실행 흐름에 연결합니다. 재시도와 중간 요약, 최종 분석과 캐시 기반 공유 결과를 회귀 검증합니다.
4. 자체 보안 및 코드 리뷰와 변이 검사를 진행합니다. 전체 검사와 문서 검사, 부모 리뷰 후 필요한 수정과 로컬 커밋을 마칩니다.

- [x] 탐지 누락 재현과 메시지 경계 보호를 검증합니다.
- [x] 모든 전송 경계와 설정 정책, 실제 전송 길이를 검증합니다.
- [x] 원문 근거, 요약 선택과 재시도 회귀를 검증합니다.
- [x] 전체 검사와 자체 리뷰, 부모 리뷰 후 로컬 커밋합니다.

테스트 실행 전 확인한 의존성에는 외부 오류 보고와 분석 SDK가 없습니다. 업데이트 HTTP 요청은 본체 진입점에, OS 알림은 명령과 백그라운드 경로에 있습니다. 해당 경로와 실제 AI 호출을 실행하지 않고 Cargo를 오프라인으로 실행합니다.

## 검증과 리뷰 기록

API 키 접두사 누락과 개인키 본문 노출은 먼저 실패하는 합성 테스트로 재현했습니다. 메시지를 이을 때 앞뒤 일반 문장 때문에 단어 경계가 사라져 탐지를 놓치는 경우도 재현해 기존 규칙의 단어 경계 의존을 없앴습니다. 새 탐지 종류는 추가하지 않았으며 과다 마스킹 가능성을 문서화했습니다.

실제 요청을 만드는 함수를 통해 Anthropic과 OpenAI의 직렬화된 HTTP 본문과 인증 헤더, Codex의 최종 표준 입력을 가짜 전송으로 받았습니다. 직접 분석과 JSON 및 429 재시도는 세 공급자와 활성화 및 비활성화 조합을 검사했습니다. 중간 요약의 선택 조각과 마지막 발언, 파생 요약에 생긴 새 감지 대상, 오래된 캐시 요약의 전송, 마스킹 후 입력 증가와 표제, Codex 전체 입력의 경계값도 확인했습니다.

부모 리뷰에서 찾은 캐시 근거 검사 차이는 전체 메시지와 공통 준비 함수를 사용하도록 수정했습니다. Codex 실패 출력에서 429 분류까지 사라지는 문제는 본문을 노출하지 않는 고정 오류로 전달하도록 수정했습니다. 합성 실패 이벤트를 실제 프로세스 출력 변환 함수로 처리한 뒤 재시도하는 경로를 검사했습니다. 설정 파싱과 지원하지 않는 공급자 값, JSON 응답 파싱과 프로세스 실패에서도 원문 비밀값을 오류로 출력하지 않는지 검사했습니다.

자체 리뷰에서는 참고 발언의 길이 제한으로 긴 키의 접두사가 사라지는 실패를 재현했습니다. 참고 원문도 먼저 마스킹한 뒤 기존 표제와 예산 안에서 선택하도록 수정했으며 당일 발언과 비활성화 설정을 함께 검사했습니다. 원문과 보호된 입력에 모두 있는 인용의 파일 위치만 유지하고 비밀값이나 표식으로 만든 인용은 제외합니다.

공통 전송 마스킹과 분할 전 마스킹을 각각 잠시 꺼 본 변이 검사에서 관련 테스트가 실패했습니다. 원본 파일 바이트를 정확히 복원했습니다. 실제 AI, API 키와 사용자 세션, 알림, Obsidian 노트는 사용하지 않았습니다.

부모 추가 리뷰에서 제안한 긴 타임스탬프 로그와 개인키 본문을 실제 압축 함수에 넣어 BEGIN 표시가 사라지고 본문 꼬리가 전송되는 실패도 재현했습니다. 감지 가능한 값이 있는 입력은 압축과 서브에이전트 중간 생략을 보류하고 온전하게 공통 경계로 넘긴 뒤 마스킹합니다. 이후 남은 로그를 압축합니다. 실제 `subagent_lines`의 10,000자 요청과 결과, 임시 Antigravity 기록을 실제 어댑터로 수집한 입력도 전송 회귀로 확인했습니다. 이 두 전처리 보호를 각각 제거한 변이 검사에서도 본문과 꼬리 노출 테스트가 실패했으며 원본 바이트로 복원했습니다.

참고 입력이 온전한 원문 검사에 의존하게 되어 참고 원문도 캐시 지문에 포함하고 입력 정책 식별자를 `ai-redaction-v1`으로 갱신했습니다. 숨은 참고 접두사만 바뀌어도 지문이 달라지는 테스트를 통과했습니다. 기존 캐시 파일을 삭제하거나 일괄 수정하지 않으며 다음 실행에서 변경된 입력 정책을 판별합니다.

2026-11-02 최종 코드에서 `cargo build --offline --locked`, `cargo clippy --offline --locked --all-targets -- -D warnings`, 전체 398개 테스트와 `cargo fmt --check`가 통과했습니다. 변이 검사 복원 뒤의 결과입니다. 새 명세와 이 기록, README의 마스킹 안내 부분은 한국어 문서 검사를 통과했습니다. README 전체 검사에서는 기존 영어 부분의 엠 대시와 앞선 문단의 검토 항목이 남아 해당 부분은 보존했습니다. 부모는 추가 전처리 경계와 테스트까지 읽고 추가 필수 수정이 없다고 확인했습니다.

## 6번에 넘길 현재 경계와 한계

프로젝트별 탐색과 후속 작업 관리는 구현하지 않았습니다. 다음 작업이 AI 호출을 추가한다면 `LlmProvider`의 공통 호출과 입력 예산 검사를 사용해야 합니다. HTTP 요청 작성 함수와 Codex 실행 함수를 직접 부르면 공통 보호를 우회하므로 호출부를 추가하지 않아야 합니다.

탐지는 내장 규칙이 아는 형태에 한정됩니다. 임의의 비밀값이나 인코딩, 원문에서 이미 사라진 접두사와 별도 발언으로 해체된 모든 표현을 복원해 탐지한다고 보장하지 않습니다. 온전한 원문이 남아 있는 선택된 참고 발언의 길이 제한은 보호하지만, 선택에서 빠진 과거 발언을 새로 복구하지는 않습니다. 입력 토큰은 기존 문자 기반 추정값과 공급자 사용량을 사용하며 실제 모델의 토큰 계산이나 요약 품질은 검증하지 않았습니다. `summary`와 `slack`은 기존 기본 입력 예산을 사용하고 새 요청 제한 탐색 호출을 추가하지 않았습니다.

`redactor.enabled = false`는 보호를 명시적으로 끕니다. 메시지 경계의 보수적 검사와 끝 표시 없는 개인키 때문에 일반 문장도 가려질 수 있습니다. 원문 집계에는 선택된 참고 발언의 온전한 원문 검사도 포함합니다. 기존 로컬 캐시와 노트의 비밀값을 일괄 삭제하거나 파일을 마이그레이션하지 않았으며, 실제 인증과 외부 공급자의 동작은 확인하지 않았습니다.

감지 대상이 있는 서브에이전트 입력은 이전의 부분별 사전 제한보다 커질 수 있습니다. 명시적 비활성화에서는 해당 값도 그대로 남습니다. 이를 숨기려고 다시 중간을 자르지 않으며 최종 공급자 문자 수, 토큰 예산과 요약 조각 예산을 적용합니다. 큰 입력은 중간 요약과 부분 분석 표시 또는 예산 오류로 이어질 수 있습니다.
