# 프로젝트와 질문 및 후속 작업 회고 계획

기준 명세는 [RETROSPECTIVE.md](../SPEC-retrospective.md)입니다. 기존 어댑터 작업의 미완료 확인 항목은 보존하고 이 작업을 별도 목록으로 기록합니다.

1. 프로젝트 식별과 표시를 연결합니다. 로그의 절대 경로를 보수적으로 식별하고 캐시 지문과 결과에 연결합니다. 같은 이름의 다른 경로와 미확인 값, 비밀값을 합성 테스트로 확인합니다.
2. 제목과 질문 및 후속 작업 구조를 추가합니다. 원문 검증, 요약 선택 범위와 캐시 검사를 함께 확장하고 한국어 및 영어 프롬프트와 Codex 출력 스키마를 맞춥니다. 실제 의미 추출과 구조 검증을 구분합니다.
3. 터미널과 Markdown에 프로젝트별 제목과 텍스트 상태를 표시합니다. 기존 `curiosities`를 미확인으로 보존하고 공유 요약 입력은 프로젝트 구분만 보완합니다.
4. 합성 통합 테스트와 전체 빌드, Clippy, 테스트 및 포맷 검사를 통과시킵니다. 자체 리뷰와 부모 리뷰의 실제 문제를 수정하고 검증한 변경을 선택해 로컬 커밋합니다.

- [x] 프로젝트 식별과 표시
- [x] 제목과 상태 추출 및 원문 검사

각 단계에서 관련 테스트를 먼저 실패시킨 뒤 최소 구현으로 통과시킵니다. 단계마다 의미 있는 변경을 검증하고 커밋합니다. 최종 상태에서 통과한 검사를 보고 목적으로 반복하지 않습니다.

## 검증과 리뷰 기록

2026-11-02 최종 코드에서 `cargo build --offline --locked`, `cargo clippy --offline --locked --all-targets -- -D warnings`, `cargo test --offline --locked --quiet`의 421개 테스트와 `cargo fmt --check`가 통과했습니다. 새 명세와 계획 및 README의 새 안내는 한국어 문서 검사를 통과했습니다.

프로젝트 식별은 명시된 절대 작업 경로만 사용합니다. 전체 결과를 프로젝트부터 묶고 소스와 전체 ID는 세션마다 유지합니다. 부모 리뷰에서 요청한 여러 소스의 동일 프로젝트 합치기와 이름이 같은 다른 경로 분리, 작업 제목 아래 세부 표제 계층을 반영했습니다. 공유 요약은 현재 로그로 캐시 프로젝트를 다시 확인한 뒤 실행 내 구분 키와 표시 이름을 전달하며 전체 경로를 새 입력에 추가하지 않습니다. 경로가 미확인인 세션은 공유 입력에서도 각각 구분합니다.

제목과 질문 및 후속 작업을 합성 원문과 대조했습니다. 원문 ID와 인용, 발언자, 날짜 구분, 엄격한 발언 순서와 선택된 요약 조각을 검사합니다. 근거 일부가 잘못되면 새 상태 연결 전체를 제외하므로 철회만 사라져 작업이 되살아나지 않습니다. 기존 질문은 상태와 근거 미확인으로 보존합니다. 새 구조가 없는 캐시에는 상태를 채우지 않습니다. 입력 정책 지문을 갱신했으며 사용자 캐시를 일괄 수정하지 않았습니다.

자체 리뷰와 부모 리뷰에서 사용자 해결 확인 뒤의 AI 추가 답변이 해결 미확인으로 표시되는 사례를 재현했습니다. 마지막 사용자 해결 또는 미해결 명시를 우선하도록 수정했습니다. 반대 사용자 상태로의 변경과 이후 AI 답변, 사용자 요청과 AI 제안 및 진행 요청, 완료 보고와 철회, 과거 질문과 오늘 변경, 캐시 왕복과 근거 재검증을 확인했습니다. 같은 발언의 재사용과 역순, 마스킹된 인용 및 생성된 마스킹 표식, 없는 발언과 선택되지 않은 조각도 검사했습니다.

Anthropic과 OpenAI의 실제 요청 작성 함수, Codex의 최종 표준 입력을 가짜 전송으로 받았습니다. 한국어와 영어 및 직접 분석과 중간 요약 경로에서 새 필드가 공통 검증을 거치는지 확인했습니다. 모델이 반환한 가짜 프로젝트는 로컬 수집 정보로 대체했고 프로젝트 경로가 새 전송에 추가되지 않았습니다. 새 텍스트와 식별 정보가 Markdown 및 HTML 표식, 링크나 터미널 제어문자로 해석되지 않는지 확인했습니다.

원문 순서 조건을 `>`에서 `>=`로 바꾼 변이에서 같은 발언 재사용 테스트가 실패했습니다. 선택된 요약 조각 검사를 잠시 제거한 변이에서도 관련 테스트가 실패했습니다. 두 파일을 원래 바이트로 정확히 복원한 뒤 위 전체 검사를 통과했습니다. 부모는 최신 상태 검증과 표시 및 공유 입력과 통합 테스트를 읽고 추가 필수 수정이 없다고 확인했습니다.

새 프롬프트가 길어져 계획용 시스템 입력 추정치를 5,000으로 조정했습니다. 긴 세션 마스킹 회귀의 고정 2,000 입력 예산은 실제 한국어 프롬프트 추정치와 대화 1,000의 합으로 바꾸고 실제 전송 본문이 그 예산 안인지 계속 검사했습니다. 첫 조각과 마지막 두 조각 보존 및 전체 입력 상한은 유지합니다.

## 남은 한계와 완료 범위

실제 AI의 의미 추출 품질과 공급자 서비스의 응답은 검사하지 않았습니다. 코드는 인용의 존재와 위치 및 구조를 확인하지만 그 발언이 해당 질문의 답인지, 해결과 철회를 뜻하는지 독립적으로 판정하지 못합니다. 완료 보고를 실제 실행 성공으로 승격하지 않습니다. 현재 파일시스템의 Git 정보로 과거 저장소를 복원하지 않으므로 하위 경로와 별도 체크아웃 및 심볼릭 링크는 나뉠 수 있습니다. 감지 가능한 비밀값 보호는 기존 내장 규칙의 범위입니다.

기존 12개와 4,000자 참고 한도와 긴 세션의 부분 분석 한계는 유지합니다. 전체 날짜의 작업 추적이나 수동 상태 관리 및 새로운 개선 과제를 추가하지 않았습니다. 실제 AI, 실제 API 키, 앱 본체와 알림 및 사용자 세션과 캐시 또는 Obsidian 노트의 일괄 변경은 하지 않았습니다. 푸시, PR과 배포도 하지 않았습니다. 앞선 1~5번의 근거, 긴 세션, 여러 날 맥락, 메모 보존과 전송 보호 경계를 유지한 상태에서 마지막 6번을 구현했습니다. 전체 1~6번의 최종 확인은 부모 채팅에 인계합니다.
