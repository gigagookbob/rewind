# 일일 노트 보존 명세

## 목적과 성공 조건

`today`와 `summary`를 반복 실행해도 사람이 쓴 메모, 제목, 앞머리 정보와 다른 자동 결과를 보존합니다. 최초 저장, 캐시 재출력, 재분석과 명령 순서 변경에 같은 정책을 적용합니다. 기존 출력의 근거, 정정 분류, 참고 시각과 부분 분석 표시는 바꾸지 않습니다.

## 저장 정책

- 분석과 진행 요약을 각각 `analysis`와 `summary` HTML 주석 영역으로 저장합니다. 시작 표시에는 형식 버전과 본문의 FNV-1a 64비트 체크섬을 넣습니다. 체크섬은 실수로 바뀐 본문을 감지하는 용도이며 보안 검증이 아닙니다.
- 표시와 본문이 온전한 영역만 제자리에서 교체합니다. 다른 내용은 공백과 줄바꿈까지 그대로 보존합니다. 영역이 없으면 파일 뒤에 한 번 추가합니다.
- 표시 없는 기존 파일은 기존 버전의 결과인지 사용자 문서인지 추측하지 않고 모두 보존합니다. 따라서 첫 이행에서는 이전 분석과 새 영역이 함께 보일 수 있습니다. 실제 노트를 일괄 변환하지 않습니다.
- 사람이 자동 영역을 수정했거나 표시가 중복, 손상, 미완성이면 저장을 중단합니다. 제목만으로 소유권을 추정하지 않습니다. 코드 상자의 제목이나 표시 예시는 갱신 대상으로 삼지 않습니다. 안전하게 경계를 확인할 수 없는 입력은 원본을 보존하고 오류로 알립니다.
- 날짜별 고정 잠금 파일에 표준 라이브러리 배타 잠금을 잡은 뒤 읽고 수정합니다. 다른 rwd가 사용 중이면 기다리지 않고 실패합니다. 같은 폴더의 새 임시 파일에 쓰고 동기화한 뒤 이름을 바꿉니다. 기존 파일의 권한을 보존하고 심볼릭 링크는 거부합니다.
- 교체 직전에 원본을 다시 읽어 외부 변경을 확인합니다. 외부 편집기는 잠금에 참여하지 않으므로 마지막 확인과 교체 사이의 동시 편집까지 보장하지는 못합니다. 동기화 서비스와 전원 장애의 내구성도 별도 보장하지 않습니다.
- 읽기, 충돌과 저장 실패를 호출자에 반환합니다. `today`, `summary`와 백그라운드 실행은 저장 실패 후 성공 안내를 계속하지 않습니다.

## 구조와 구현 방식

Rust 2024, 기존 의존성과 표준 라이브러리만 사용합니다. 저장 정책과 파일 처리는 `src/output/`에 두고 명령은 결과를 전달합니다. `Result`와 `?`로 오류를 호출자에 전달합니다.

`File::try_lock`은 즉시 배타 잠금을 시도하고 실패하면 오류를 돌려줍니다. 잠금용 `File`이 함수 끝에서 해제되면 운영체제 잠금도 풀립니다. 임시 경로를 감싼 `PendingFile`의 `Drop`은 성공과 오류 반환 모두에서 임시 파일 정리를 시도합니다. `AtomicU64`는 같은 프로세스의 여러 호출이 임시 파일 일련번호를 겹쳐 쓰지 않게 합니다. 실제 파일 생성도 `create_new`로 수행하므로 이미 있던 파일은 덮어쓰지 않습니다. 별도 데이터베이스나 새 크레이트 대신 표준 라이브러리를 선택한 이유입니다. API는 Context7의 [Rust 표준 라이브러리 문서](https://doc.rust-lang.org/stable/std/fs/struct.File.html)에서 확인했습니다.

```rust
let saved = output::save_to_vault(&vault_path, date, &markdown)?;
```

본문 비교와 수정은 순수 함수로 검증하고 파일 저장은 합성 Markdown과 임시 디렉터리로 검증합니다. 본체, 실제 노트와 외부 AI는 실행하지 않습니다. 기존 `tasks/plan.md`와 `tasks/todo.md`를 보존하고 이번 작업 목록은 `tasks/note-preservation.md`에 둡니다.

## 검증 명령과 범위

`cargo test --offline --locked`, `cargo build --offline --locked`, `cargo clippy --offline --locked --all-targets -- -D warnings`, `cargo fmt --check`를 `cli`에서 실행합니다. 실행 전 테스트 진입점이 외부 오류 보고, 분석과 알림을 호출하지 않는지 확인합니다. 합성 자료로 저장 순서, 재저장, 구 파일, 코드 상자, 표시 충돌, 읽기 실패와 교체 실패를 검증합니다. 핵심 조건을 잠깐 약화한 회귀 검사 뒤 원래 코드를 복원합니다.

5번 전체 AI 호출의 마스킹과 6번 탐색은 이번 범위에 포함하지 않습니다. 새 의존성, 배포, 푸시와 실제 노트 변경도 하지 않습니다. 현재 미정 요구사항은 없습니다.
