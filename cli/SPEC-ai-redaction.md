# 모든 AI 전송의 민감정보 마스킹

## 목적과 범위

`today` 직접 분석, 긴 세션의 중간 요약과 최종 분석, `summary`, `slack`과 재시도에 같은 보호를 적용합니다. 기존 탐지 규칙을 사용하며 API 키의 접두사 누락과 개인키 본문 노출만 최소한으로 보완합니다. 새 탐지 엔진, 실제 AI 호출, 사용자 캐시와 노트의 일괄 변경, 6번 기능은 포함하지 않습니다.

## 설계와 성공 조건

- 공급자가 설정을 읽을 때 마스킹 정책도 함께 보유합니다. `[redactor]`가 없으면 활성화하고 `enabled = false`일 때만 비활성화합니다. 설정 누락이나 읽기 실패는 공급자 로딩 실패로 처리해 전송하지 않습니다.
- 원문 메시지는 분할 전 마스킹합니다. 탐지할 값이 메시지 사이에 걸친 경우에도 이어진 내용에서 범위를 찾고 각 메시지에 해당하는 부분을 가립니다. 발언 순서와 원문 위치는 보존합니다. 원문 마스킹 수는 재시도 전에 한 번 집계합니다.
- 과거 참고 발언도 보관된 온전한 원문을 먼저 마스킹하고, 기존 참고 표제와 길이 예산 안에서 후반을 다시 고릅니다. 길이 제한으로 접두사를 잃은 키의 꼬리가 전송되는 경우를 막습니다. 비활성화 설정이면 기존 참고 입력을 유지합니다.
- 로그 압축과 서브에이전트의 중간 생략은 감지 대상이 있는 입력을 온전하게 유지해 공통 마스킹 경계로 넘깁니다. 해당 값이 쪼개진 뒤 검사하는 일을 막고, 마스킹한 뒤 남은 로그를 압축합니다. 서브에이전트의 부분별 사전 제한은 해당 입력에 한해 보류하며 최종 전송 예산과 조각 제한은 유지합니다.
- 공급자 공통 경계는 시스템 프롬프트와 대화 본문을 다시 마스킹합니다. 오래된 캐시와 중간 요약도 이 경계를 통과합니다. 인증 헤더는 마스킹 대상에 포함하지 않습니다.
- 실제 전송할 입력의 문자 수와 기존 방식의 예상 토큰 수를 확인합니다. 프롬프트, 재시도 안내와 조각 표제도 포함하고, 초과 입력은 오류로 반환하며 자르지 않습니다.
- HTTP 요청은 만들어진 요청 객체, Codex는 완성된 표준 입력을 검사할 수 있게 구성합니다. 가짜 전송은 실제 요청 작성 경로를 통과하고 외부 네트워크나 Codex 프로세스를 실행하지 않습니다.
- 근거는 원문과 마스킹된 전달 내용 모두에 존재하는 인용만 인정합니다. 비밀값이 포함된 인용과 마스킹 표식으로 만든 인용은 버리고 복원하지 않습니다. 기존 정정 순서, 부분 분석과 과거 참고 표시를 유지합니다.
- 오류에는 공급자가 반환한 본문과 프로세스 출력이 그대로 노출되지 않게 합니다. 비밀값을 포함할 수 있는 응답의 내용을 진단 로그로 사용하지 않습니다.

## 구현과 검증

Rust 2024와 기존 의존성을 사용합니다. 구현은 `src/redactor/`, `src/analyzer/`에 두고 테스트는 같은 모듈의 `#[cfg(test)]`와 전송 회귀 테스트 모듈에 둡니다. 이름과 오류 처리, 포맷은 기존 관례를 따릅니다. 예를 들어 `let request = builder.build()?;`로 요청 작성 오류를 반환합니다.

합성 비밀값과 임시 자료로 직접 분석, 중간 요약, 파생 결과와 캐시, 설정 비활성화, JSON 및 요청 제한 재시도, 경계 분할, 인용과 입력 초과를 검증합니다. 실제 인증과 모델의 요약 품질은 검증하지 않습니다. 새 의존성과 외부 전송은 추가하지 않습니다.

`cli/`에서 다음 명령을 실행합니다.

```sh
cargo build --offline --locked
cargo clippy --offline --locked --all-targets -- -D warnings
cargo test --offline --locked
cargo fmt --check
```
