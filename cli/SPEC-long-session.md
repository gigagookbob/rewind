# 긴 세션의 후반 보존 명세

긴 세션에서 뒤늦은 결정 변경, 실패 해결과 사용자 정정이 분석 재료에서 빠지는 문제를 고칩니다. 새 의존성과 외부 AI 검증은 추가하지 않습니다.

## 동작과 범위

- 중간 요약 호출은 실행 시도당 최대 세 번입니다. 세 조각 이하는 모두, 네 조각 이상은 첫 조각과 연속된 마지막 두 조각을 원래 순서대로 처리합니다.
- 제외한 중간 조각의 번호와 전체 조각 수를 터미널, 분석 입력과 결과의 `work_summary`에 명시합니다. 이 표시는 모델 응답에 맡기지 않으며 캐시와 Markdown에도 남깁니다.
- 각 입력은 역할, 발언 ID와 프롬프트 여유를 포함해 문자 상한과 추정 토큰 상한을 지킵니다. 한 발언이 길면 문자 경계에서 나누고 각 부분에 원래 발언 ID를 유지합니다. 담을 수 없는 최소 입력과 빈 입력은 오류로 처리합니다.
- 요약은 시간순 변화와 최종 상태, 미해결 여부를 구분합니다. 합성 설명을 원문 인용으로 인정하지 않으며 기존 원문 대조, 정정 종류와 대화 순서 검사를 유지합니다.
- 합친 요약이 최종 분석 입력 제한을 넘으면 자르지 않고 오류를 반환합니다. 짧은 세션의 직접 분석은 유지합니다.

## 코드와 검증

Rust 2024와 기존 Tokio, Serde를 사용합니다. 로직과 단위 테스트는 `src/analyzer/summarizer.rs`와 `executor.rs`, 프롬프트는 `prompts/chunk_summarize_*.md`, 동작 설명은 `README.md`와 `docs/ARCHITECTURE.md`에 둡니다. 기존 `Result`와 `?` 방식으로 오류를 반환합니다.

```rust
let chunks = split_into_chunks(messages, token_budget, char_budget)?;
```

검증 명령은 `cargo test --offline --locked`, `cargo build --offline --locked`, `cargo clippy --offline --locked --all-targets -- -D warnings`, `cargo fmt --check`입니다. 합성 입력과 순수 함수로 A에서 B로 변경, 실패 해결, 마지막 정정, 큰 발언, 순서, 호출 대상 수와 입력 제한을 검사합니다. 실제 모델의 의미 보존 품질은 검증하지 않습니다.

실제 사용자 로그와 비밀값을 외부로 전송하지 않습니다. 여러 날 수집, 일일 노트 덮어쓰기, 전체 마스킹 개선과 탐색 기능은 별도 범위입니다. 기존 캐시는 자동 재분석하지 않으며 새 동작은 `--no-cache`로 명시적으로 적용할 수 있습니다.
