# 프로젝트와 질문 및 후속 작업 회고 명세

## 목적과 범위

기존 `today`의 터미널과 Markdown에서 프로젝트와 읽을 수 있는 작업 제목으로 세션을 찾고 질문과 후속 작업의 대화상 상태를 확인합니다. 소스 이름, 전체 세션 ID와 원문 위치는 유지합니다. 별도 서비스, 전역 작업 추적, 수동 상태 편집, 외부 이슈나 알림 연동은 추가하지 않습니다.

## 기능 경계와 순서

| 기능 | 책임 | 앞선 기능 |
| --- | --- | --- |
| 프로젝트 식별 | 로컬 로그 메타 정보로 프로젝트를 구분합니다. | 없음 |
| 근거 있는 상태 | 제목과 질문 및 후속 작업을 원문과 시간순으로 대조합니다. | 기존 근거 검사 |
| 회고 표시 | 두 기능의 결과를 터미널, Markdown과 공유 요약 입력에 사용합니다. | 프로젝트 식별, 근거 있는 상태 |

세 기능은 하나의 일일 회고 경로를 구성합니다. 구현 순서는 프로젝트 표시, 상태 추출과 표시, 통합 검증입니다.

## 식별 정책

프로젝트는 Codex의 `session_meta.cwd`와 Claude의 사용자 기록 `cwd`에 명시된 절대 로컬 경로로 식별합니다. `.`과 `..` 및 중복 구분자만 정규화합니다. 현재 Git이나 파일시스템을 조사해 과거 저장소를 추정하지 않습니다. 마지막 경로 이름을 표시하고 전체 경로도 함께 보여 줍니다. 전체 결과를 프로젝트부터 묶고 각 세션에 소스 이름을 유지하므로 같은 프로젝트의 여러 도구 세션을 함께 찾을 수 있습니다. 이름이 같아도 경로가 다르면 합치지 않습니다. 하위 디렉터리, 별도 체크아웃과 심볼릭 링크는 같은 저장소임을 확인할 자료가 없으므로 별도로 남습니다.

경로가 없거나 상대 경로, URL, 감지 가능한 비밀값을 포함한 경로 또는 여러 경로가 충돌하는 세션은 프로젝트 미확인으로 표시합니다. Antigravity는 지원하는 로그에 프로젝트 메타 정보가 없으므로 미확인입니다. AI 응답의 프로젝트 값은 신뢰하지 않으며 로컬 수집 결과만 사용합니다. 프로젝트 경로는 새 분석 AI 입력에 추가하지 않습니다. 공유 요약에는 경로 대신 실행 내 구분 번호와 안전한 표시 이름을 전달합니다.

## 상태 정책

작업 제목은 짧은 설명과 사용자 발언 근거를 받습니다. 검증할 수 없으면 작업 제목 미확인으로 표시합니다. 제목을 세션 ID에서 추측하지 않습니다.

질문은 사용자 원문 근거와 시간순 변경 목록으로 보관합니다. 변경 종류는 AI 답변, 사용자 해결 확인, 사용자 미해결 명시입니다. 답변이 없으면 답변 및 해결 미확인입니다. AI 답변만 있으면 답변 있음, 해결 미확인입니다. 사용자가 해결이나 이해를 확인해야 해결 확인으로 표시합니다. 마지막 사용자 해결 또는 미해결 명시는 이후 AI 답변으로 덮어쓰지 않으며 이후 사용자의 반대 확인이 있으면 갱신합니다. 명시적으로 남은 문제는 미해결 명시로 표시합니다. 기존 `curiosities`는 상태와 근거 미확인으로 보이며 새로운 질문으로 임의 변환하지 않습니다.

후속 작업의 출발은 사용자 요청 또는 AI 제안입니다. 이후 진행 요청과 철회는 사용자 발언, 완료 보고는 사용자 또는 AI 발언으로 연결합니다. 완료 보고는 독립적인 실행 검증과 구분합니다. 주체나 출발이 불명확하면 새 항목에서 제외합니다. 완료 또는 철회 뒤 단순한 진행 요청으로 미완료 상태를 되살리지 않습니다. 새 요청은 별도 작업으로 추출합니다. 담당자는 추정하지 않습니다.

원래 질문이나 작업이 과거 참고에만 있어도 오늘 답변이나 상태 변경이 있으면 이전 근거와 연결합니다. 모든 근거가 과거이면 당일 항목에서 제외합니다. 기존 12개와 4,000자 참고 범위를 넓히지 않습니다. 자동 영역은 대화에서 확인한 상태를 읽는 용도이며 체크박스를 제공하지 않습니다. 수동 메모는 자동 영역 밖에 씁니다.

## 구조와 검증

`src/analyzer/insight.rs`와 별도 회고 타입 모듈에 결과를 정의하고 기존 `evidence.rs` 경계에서 새 근거도 검증합니다. 수집은 `src/sources/`, 표시는 `src/output/`과 `src/commands/`에 둡니다. 테스트는 인접 모듈과 합성 통합 표본을 사용합니다. 기존 Rust 2024와 Serde 의존성을 사용하며 의존성을 추가하지 않습니다.

```rust
#[serde(default)]
pub questions: Vec<Question>,
```

위 기본값은 과거 캐시에 새 목록이 없으면 빈 목록으로 읽습니다. 상태를 미해결 또는 완료로 채우는 기본값을 사용하지 않습니다. 원문 인용의 존재, 실제 발언자, 날짜 구분, 발언 순서와 선택된 요약 조각을 검사합니다. 캐시에서도 근거를 다시 검사하고 실패한 새 제목과 상태 항목을 제거합니다. 기존 메모 보호와 마스킹 경계를 유지합니다.

인용의 의미가 실제 질문의 답인지, 해결이나 철회 표현인지 코드는 완전히 판정하지 못합니다. 프롬프트는 이를 지시하며 합성 응답으로 구조와 원문 대조를 검증합니다. 실제 AI 추출 품질은 별도 측정 대상입니다.

## 검증 명령과 경계

명령은 `cli/`에서 실행합니다.

```bash
cargo build --offline --locked
cargo clippy --offline --locked --all-targets -- -D warnings
cargo test --offline --locked
cargo fmt --check
```

합성 로그, 가짜 전송과 임시 파일로 여러 프로젝트, 동일 표시 이름, 상태 구분, 과거와 당일 연결, 캐시 호환성과 근거 누락 및 역순을 검사합니다. 새 텍스트의 터미널 제어문자와 Markdown 및 HTML 해석을 막습니다. 실제 AI 호출, API 키, 앱 실행, 알림과 사용자 자료 일괄 변경은 하지 않습니다. 요청 범위만 로컬 커밋하며 푸시와 배포는 하지 않습니다.
