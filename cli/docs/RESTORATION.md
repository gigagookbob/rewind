# CLI 로컬 복원 기록

2026년 10월 20일에 `gigagookbob/rewind`의 `1656efc4`를 바탕으로 CLI를 복원했습니다. 웹사이트는 이번 작업 범위에 포함하지 않았습니다.

## 가져온 수정

기존 `gigagookbob/rwd`의 `v0.13.17`에서 다음 수정을 가져왔습니다.

- `2676e32`: 명시된 메타데이터를 확인해 Codex 하위 에이전트 세션을 분석에서 제외합니다.
- `a2d1b0e`: Claude 하위 에이전트의 sidechain 기록을 집계 전에 제외합니다.
- `523bd65`: API 키에 적힌 `${VAR}`를 실행 시 환경변수에서 읽습니다. 원본 테스트의 `unsafe` 환경변수 변경은 사용하지 않고 현재 프로세스의 `PATH`를 읽어 검증합니다.
- `16473e2`: 일반 텍스트 요약에 JSON 출력을 강제하지 않습니다. 통합본의 공통 요청 함수는 유지하고 분석 요청과 텍스트 요청의 출력 형식을 구분합니다.

로그 압축은 통합본에 이미 들어 있어 다시 가져오지 않았습니다. 6월에 정리한 공통 분석 흐름과 설치 주소도 유지합니다. 버전은 `0.13.17`로 맞췄으며 새 릴리즈나 태그를 만들지는 않았습니다.

## 최근 로그 호환 처리

현재 Codex Desktop 로그는 사용자 발화를 `response_item`의 `message`, `role=user`, `input_text` 블록으로 기록합니다. 이 형식도 읽도록 보완했습니다. 앱이 삽입한 AGENTS 지침, 환경 정보와 열린 Page 정보는 사용자 발화에서 제외합니다.

이전 형식의 `event_msg`와 같은 발화가 5초 안에 함께 기록되면 한 번만 집계합니다. 나중에 같은 질문을 다시 하거나 이어서 연 대화의 저장 형식이 바뀌어도 새 발화는 유지합니다.

모델을 따로 지정하지 않으면 Codex CLI에 설정된 모델을 사용합니다. 이전 기본값인 `gpt-5.4`가 현재 ChatGPT 로그인에서 지원되지 않아 실제 분석이 실패하는 것을 확인한 뒤 바꿨습니다. `rwd config codex-model`로 명시한 모델은 그대로 우선합니다.

## 검증 명령

`cli/`에서 다음 명령으로 확인합니다.

```bash
cargo fmt --check
cargo clippy --locked -- -D warnings
cargo test --locked
cargo build --release --locked
```

실제 일지 생성은 기존 Codex 로그인으로 `target/release/rwd today --date 2026-10-20 --no-cache --lang ko -v`를 실행해 확인합니다. 검증 중에는 출력 경로만 별도 폴더를 가리키는 임시 설정을 사용하고, 종료 시 기존 설정과 해당 날짜의 캐시를 원래 상태로 복구합니다. 설치된 실행 파일과 Obsidian 일지는 덮어쓰지 않습니다.

## 확인한 결과

기존 테스트 208개를 확인한 뒤 복원과 호환 처리의 회귀 테스트를 추가했습니다. 최종 테스트 231개, 포맷 검사, 경고를 오류로 취급한 Clippy 검사와 릴리즈 빌드를 통과했습니다. OpenAI 요청 형식의 조건을 반대로 바꿨을 때 회귀 테스트가 실패하는 것도 확인했습니다.

10월 20일의 실제 Codex 대화 3개로 한국어 Markdown 일지와 분석 캐시를 생성했습니다. 사용자 요청과 어시스턴트 답변에 나온 세 작업이 각각 구분되는지 대조했습니다. 진행 중인 대화는 분석 시작 시점까지만 요약합니다. 해당 날짜에 Claude 대화는 없어 Claude 경로는 단위 테스트로 확인했습니다.

기존 설정 파일은 바이트 단위로 복구했고 설치된 실행 파일의 해시도 바뀌지 않았습니다. 검증용 일지는 별도 출력 폴더에 남겼습니다. 푸시, PR 생성, 저장소 보관 해제와 배포는 하지 않았습니다.
